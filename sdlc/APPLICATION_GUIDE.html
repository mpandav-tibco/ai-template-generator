BWCE AI Integration REPO Generator

1) What This Application Does

Natural Language to Integration Spec Converts prompts like "from s4hana to poc for article data using rest to kafka" into structured BWCE config fields.
Template Selection and Generation Detects best matching template and executes code generation through shell automation.
Chat + API Experience Supports Web Chat UI, CLI chatbot, and REST APIs for human and programmatic usage.
Enterprise-Friendly Outputs Produces repository structure, updates IKD registry files, and prepares configs/scripts for delivery pipelines.

3) Tools, Plugins, LLMs, and Models

Core tools required

Python 3.10+ pip Git Bash (Git Bash/WSL)

Why: Python runs FastAPI/chat modules, Bash runs the generation script, and Git is required for template/source control workflows.

Recommended VS Code plugins

  • Python (Microsoft): run/debug Python code.
  • Pylance: faster IntelliSense and type checks.
  • Docker: manage Docker and Compose setup.
  • YAML: edit deployment/config files safely.
  • REST Client or Thunder Client: quickly test APIs.

LLM backends supported

Ollama (Local, preferred for offline) Good for private/local execution with no per-call cloud charges.
OpenAI-compatible endpoints Useful when you already have hosted model endpoints.
Anthropic Optional cloud LLM backend.
No LLM Mode Regex/rule fallback still works for many requests.

Model recommendations

  • qwen2.5:7b: balanced quality and speed for local use.
  • llama3.1:8b: strong general extraction quality.
  • llama3: stable fallback model.

4) How to Install

  1. Open terminal at project root.
  2. Create virtual environment and activate.
  3. Install dependencies.
  4. Create .env from .env.example.
  5. (Optional) install and run Ollama, then pull a model.

Windows CMD

cd /d c:\Projects\Automations\bwce_ai_usecase\bwce-ai-generator\bwce-ai-generator
python -m venv .venv
call .venv\Scripts\activate.bat
python -m pip install -r requirements.txt
if not exist .env copy .env.example .env

Optional Ollama setup

ollama serve
ollama pull qwen2.5:7b

6) Generation Modes (Full vs Config-Only)

Use full mode for first-time generation. Use config-only mode to refresh config and job artifacts for an existing repository without regenerating code.

Full mode

bash scripts/GenerateCodeFromTemplate.sh \
  <template_type> <bitbucket_project> <bitbucket_url> <object_name> <cdm> \
  <interface_type> <source_system> <target_system> <interface_id> <scenario_id> \
  <environment> <bw_profile> <email> <k8s_domain> <need_secret> <unique_id> [country_code]

Config-only mode

bash scripts/GenerateCodeFromTemplate.sh \
  <template_type> <bitbucket_project> <bitbucket_url> <object_name> <cdm> \
  <interface_type> <source_system> <target_system> <interface_id> <scenario_id> \
  <environment> <bw_profile> <email> <k8s_domain> <need_secret> <unique_id> [country_code] \
  --config-only

Config-only mode reuses existing output from BuildHistory first, then Data/GeneratedCode, and regenerates configs/jobs only.
