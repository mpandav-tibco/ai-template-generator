BWCE AI Integration Template Generator

VS Created by Vishnu Singh · Apr 09, 2026 · Operational

An AI-powered accelerator that generates production-ready BWCE (TIBCO BusinessWorks Container Edition) integration repository templates through natural language interaction. Developers describe their integration requirement in plain English — the system extracts source/target/object details, asks follow-up questions for anything missing, then produces a fully scaffolded repository with CI/CD pipelines, Git initialisation, Kubernetes manifests, and Bitbucket integration — all in seconds.

Metadata Used / To be Used

Integration metadata for each generated interface is captured and persisted:

  • Generation Registry — SQLite database (accelerator_registry.db) for duplicate detection and idempotent re-generation
  • Go-Live Tracker — Tilde-delimited CSV audit trail (GoLiveTracker/CodeGenerateTracker.csv)
  • Build Metadata — generation-metadata.json & generation.properties per repository
  • Environment Manifests — Per-environment configs (DEV, SIT, UAT, PROD)

Core Components

Component File Description
REST API Server src/api.py FastAPI application defining all HTTP endpoints — session management, chat processing, health checks, legacy extraction & generation endpoints. Serves the Web Chat UI.
NLU Engine src/chatbot.py Core natural language understanding: IntegrationSpec dataclass, LLMBackend class (Ollama/OpenAI/Anthropic), regex parser, alias mappings, and template generator.
Interactive Chat src/interactive_chatbot.py Multi-turn conversation engine — processes messages, detects integration patterns, auto-scores templates, generates follow-up questions, and handles slash commands.
Accelerator Service src/accelerator/service.py Orchestrator for the full generation pipeline: validate → name → check registry → materialise template → write config → create Bitbucket repo → scaffold CI/CD → init Git → record → notify.
Template Engine src/accelerator/template_engine.py Copies template directory to output, replaces all {{PLACEHOLDER}} tokens across files, and renames paths containing placeholders.
Naming Engine src/accelerator/naming.py Generates sanitised repository names: {source}-{object}-{target}[-{id}][-{country}]-{type}, max 50 chars.
Validators src/accelerator/validators.py Input normalisation & validation for all fields, including email domain restrictions and Bitbucket URL format checks.
GitOps src/accelerator/gitops.py Creates remote Bitbucket repositories, initialises local Git repos with main and release/1.0.0 branches, and pushes to remote.
CI/CD Scaffolding src/accelerator/cicd.py Generates GitHub Actions workflow, Jenkinsfile, and K8s deployment YAMLs per environment.
Registry src/accelerator/registry.py SQLite database + CSV tracker. Enables duplicate detection and idempotent re-generation.
Kubernetes Ops src/accelerator/k8s_operations.py Built-in kubectl wrapper for listing pods/deployments/services, scaling, restarting, and fetching logs.
Notifications src/accelerator/notify.py Non-blocking webhook POST and SMTP email notifications on repository creation.

Deployment Options

Option 1 — Local CLI (no Docker needed)

python -m venv .venv .venv\Scripts\activate # Windows pip install -r requirements.txt python -m src.chatbot # CLI chatbot uvicorn src.api:app --reload --port 8080 # Web UI + API

Option 2 — Docker Compose

ℹ️

Includes three services: bwce-ai (app, port 8080), ollama (LLM server, port 11434), and swagger-ui (API docs, port 8081).

docker compose up -d --build docker exec ollama ollama pull llama3 # First time only (~4 GB) # Open http://localhost:8080

Option 3 — Kubernetes

docker build -t bwce-ai-generator:latest . docker tag bwce-ai-generator:latest <registry>/bwce-ai-generator:latest docker push <registry>/bwce-ai-generator:latest kubectl apply -f k8s/deployment.yaml kubectl port-forward svc/bwce-ai-generator 8080:80
📝

The K8s manifest includes a Deployment (1 replica, 256Mi–512Mi RAM, 250m–1 CPU), Service (ClusterIP 80→8080), ConfigMap with LLM settings, and liveness/readiness probes on /health.

Potential Impact

🚀

Accelerated delivery — What previously took hours of manual scaffolding, copy-pasting, and configuration is now accomplished in seconds through a natural-language conversation.

  • Eliminates manual boilerplate — No more copying template directories, manually replacing placeholders, or forgetting configuration steps.
  • Standardises integration repositories — Every generated repo follows the same structure, naming conventions, CI/CD pipeline, and Kubernetes manifest format.
  • Reduces onboarding time — New integration engineers can produce correctly-structured repositories on day one without deep knowledge of BWCE conventions.
  • Built-in governance — Duplicate detection via SQLite registry prevents accidental re-generation. Go-Live tracker provides a full audit trail.
  • Operations visibility — Integrated Kubernetes operations (pod listing, log fetching, scaling) provide immediate post-deployment observability.
  • Supports "Always Live" goal — Faster repository creation means quicker integration delivery, improving application availability and resiliency.
